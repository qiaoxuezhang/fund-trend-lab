# 净值罗盘

一个面向中国场外公募基金的本地优先趋势研究工具。输入基金代码或名称后，可查看历史净值、NAV-KDJ、MA、MACD、RSI、回撤、波动率、趋势等级、历史相似状态以及简化信号回测。

图表支持近 `3个月`、`6个月`、`1年`、`3年` 和全部历史区间。KDJ、MACD、RSI 均提供独立图例；短区间净值样本不足时，回测会明确显示“样本不足”，不会回退并冒充为该区间结果。

公开版本不内置任何个人基金、金额或收益率。每个新浏览器默认空组合，用户自行添加基金；组合监控、分组、成本、止盈目标和风险设置保存在该浏览器中。

## 启动

Windows 下双击 `start.cmd`，或在 PowerShell 中运行：

```powershell
.\start.ps1
```

本机浏览器打开：

```text
http://127.0.0.1:4173
```

同一 Wi-Fi 下的手机或电脑可以打开当前局域网地址：

```text
http://192.168.31.151:4173
```

局域网 IP 可能在路由器重连后变化；长期推广应使用云平台固定 HTTPS 地址，而不是开放家庭路由器端口。

如果电脑已安装 Node.js 20 或更高版本，也可以运行：

```powershell
npm start
```

项目没有第三方运行时依赖，不需要执行 `npm install`。

## 组合监控与提醒

- 使用场外基金低频检查策略：交易时段每 60 分钟、正式净值更新窗口每 30 分钟、普通非交易时段每 2 小时、休市日每 6 小时检查一次。
- 只有发现净值日期或数值变化时，才重新下载完整历史并计算指标。
- 通过历史净值页面和基金快照接口交叉核对日期、单位净值。
- 日期延迟、数值不一致或历史样本不足时，统一显示“等待确认”，不产生新增仓位动作。
- 点击“策略与止盈目标”可以设置默认止盈目标、每只基金的单独目标和持仓成本净值。
- 点击页面的“开启提醒”后，网页保持打开或最小化时，仓位动作发生变化会发送浏览器桌面通知。

旧版本从截图金额反推的参考份额只存在原使用者浏览器中，不再写入公共前端源码。公开部署后的其他用户不会看到这些信息。客户可在策略设置中填写持仓成本净值，以校准持有收益和止盈目标。

## 公网部署

项目包含 `Dockerfile`、`compose.yaml` 和 `render.yaml`。任何支持 Docker 和 HTTPS 的平台都可以运行：

```powershell
docker compose up -d --build
```

免费邀请测试将 `HOST` 设为 `0.0.0.0`，将 `ALLOW_INDEXING` 设为 `false`。页面已经包含 Web App Manifest、Service Worker、分享入口和安装入口，可在支持 PWA 的手机或电脑上安装为独立应用。

Render Free 不需要用户数据库：自选、分组、成本、交易和目标仍只保存在当前浏览器。免费实例休眠或重新部署时只会丢失可重新生成的服务端缓存，不会删除客户本机数据。需要换设备时使用 AES-256-GCM 加密保险箱手动迁移。

完整部署与域名配置见 `DEPLOYMENT.md`，当前访问状态见 `PUBLIC_ACCESS.md`。

项目审查结论与后续路线见 `AUDIT.md`，安全问题提交方式见 `SECURITY.md`。

容器监听 `0.0.0.0:4173`，健康检查地址为 `/api/health`。生产环境必须使用 HTTPS；不能直接把开发电脑的 `4173` 端口暴露到公网。

部署到 Render 时，可以将仓库连接为 Blueprint，平台会读取 `render.yaml` 构建 Docker 服务。其他云平台使用相同 `Dockerfile` 即可。

## 指标口径

场外基金通常每天只有一个单位净值，不具备股票日线的开盘、最高、最低和收盘四价。本项目优先使用累计净值计算趋势，降低现金分红造成的机械跳空影响；页面顶部仍展示最新单位净值。`NAV-KDJ` 将最近 9 个净值日的最高累计净值与最低累计净值作为随机指标区间：

```text
RSV = (当日净值 - N日最低净值) / (N日最高净值 - N日最低净值) * 100
K = 2/3 * 前一日K + 1/3 * RSV
D = 2/3 * 前一日D + 1/3 * K
J = 3K - 2D
```

因此它适合判断净值在近期波动区间的位置和动能变化，但不等同于证券标准 KDJ。

综合趋势分还会考虑：

- 净值相对 MA20、MA60 的位置
- MA20 近 5 个净值日的方向
- NAV-KDJ 金叉、死叉与相对位置
- MACD 柱体方向及零轴穿越
- RSI 强弱及追涨风险
- 20 日和 60 日净值动量
- 当前回撤和 20 日年化波动率

## 五档动作解释

- `分批建仓`：正式净值双源校验通过，技术趋势达到阈值，有效指标同向率不低于 `70%`，基本面和风险过滤未触发否决。系统不提供一次满仓提示。
- `持有观察`：已有持仓尚未达到新增仓位、止盈或退出阈值，继续跟踪均线结构、60日动量和回撤。
- `等待确认`：趋势证据不足、样本不足、基本面拖累，或正式净值尚未完成双源校验。
- `分批止盈`：客户持有收益达到默认或单基金止盈目标，提示参考分 2 至 3 次执行。目标范围为 `5%` 至 `200%`。
- `风险退出`：20-120 日中长期弱势达到防守阈值。执行前仍需检查持有期、赎回费、资金用途和个人风险承受能力。

动作判定顺序为：数据校验、样本检查、客户止盈目标、风险退出、分批建仓、持有观察、等待确认。这样可以避免同一基金同时显示多个互相冲突的动作。

稳健、均衡、积极三种模式只调整触发阈值，不会改变底层历史数据。

系统内部保留 `-100` 到 `+100` 的原始计算分，页面统一换算为 `-10.0` 到 `+10.0` 的趋势等级。`+6` 以上表示强上行结构，`+3` 至 `+5.9` 表示改善，`-2.9` 至 `+2.9` 表示方向混合，`-3` 至 `-5.9` 表示偏弱，`-6` 以下进入防守。趋势等级衡量历史方向和持续性，不代表下一净值日的涨跌预测。

“有效指标同向率”按 `与最终趋势方向一致的非零指标数 / 全部非零指标数` 计算：低于 `55%` 表示分歧较大；`55%-69%` 仅观察；`70%-79%` 可进入候选验证；`80%` 以上表示方向证据高度一致。它不是上涨概率，也不能单独触发买入。

## 中长期趋势模型

当前趋势分主要考虑：

- 累计净值相对 MA20 的位置
- MA20、MA60、MA120 的多周期排列
- MA20 近 5 个净值日的方向
- 20、60、120 个净值日动量
- 最近 20 个净值日的上涨日占比，用作趋势持续性指标
- MACD、RSI 与低权重 NAV-KDJ 辅助信号
- 近 250 个净值日回撤和年化波动率

单日涨跌不直接进入趋势分。NAV-KDJ 只作为短周期辅助，不会单独触发分批建仓或风险退出动作。

主动管理场外基金没有可靠、连续披露的每日成交量或申赎量，因此项目不会制造“成交量指标”。详情页的“交易量”仅指客户自己记录的实际买卖金额和确认份额。对于明确跟踪指数的基金，后续可以单独映射对应指数或 ETF 的成交量和市场宽度，但必须与基金净值信号分开展示。

## 自选趋势前三与交易复盘

- 首页“趋势强度前三”只比较当前浏览器自选基金，优先展示正式净值已校验的基金，并按综合趋势等级排序；同一基金的 A/C 等份额先合并为一类，不冒充全市场排名。
- 首页“全市场板块代表”同时抽取近1月和近3个月公开排行候选，合并同一基金的 A/C 等份额，按最近披露持仓识别主导板块，同一板块只保留综合验证后最优的一只。
- 全市场候选还要通过正式净值一致性、20-120 日趋势、有效指标同向率、回撤、波动、RSI 和前五大可研究持仓财务覆盖检查。结果分为“可研究建仓”“等待回撤”“继续跟踪”“仅作强势对比”等，不把涨幅榜直接当成买入榜。
- 详情页可以记录历史买入、卖出、确认净值、金额、份额和备注；记录仅保存在当前浏览器，并自动进入加密保险箱。
- 历史交易会以买卖标记显示在累计净值图上，方便结合当时趋势结构复盘执行纪律。

## 显示颜色与客户分组

- 上涨、正收益、偏强加分使用红色。
- 下跌、负收益、偏弱扣分使用绿色。
- 数据校验成功仍使用状态绿色，不与涨跌含义混淆。
- 默认只有“我的持仓”和“未分组”。客户可以新建、删除自己的分组，并在组合表格中移动基金。
- 客户分组保存在浏览器 `localStorage`。删除自定义分组时，其中基金自动移到“未分组”。
- 系统行业标签与客户分组彼此独立：标签根据最近一期前十大持仓及权重生成，用于把持仓板块相近的基金放在相邻位置。

## 持仓公司与基本面研究

- 基金持仓来自最近一期公开季度或半年度报告，页面始终展示报告期和前十大集中度，不把披露持仓冒充当前实际仓位。
- 对前十大持仓公司读取最新标准化财报、公告、公司相关新闻以及行业政策信息，并展示各自披露日期或发布时间。
- 公司研究分主要依据营收增速、归母净利润增速、净利润正负、ROE、毛利率和经营现金流；公告关键词只占较低权重。
- 基金基本面分按持仓权重聚合。财报覆盖足够时，组合页综合分使用 `75%` 趋势分和 `25%` 基本面分。
- 基本面偏弱可以把技术面的新增仓位候选降级为等待确认；基本面不能脱离趋势单独生成分批建仓提示。
- 新闻和政策搜索必须命中公司名，或同时命中行业词与政策词。它们仅用于背景核验，不直接计入买卖分，避免短期消息噪声主导判断。
- 系统按前十大持仓的加权重合度计算相似基金。该相似度反映已披露组合，不代表当前实时持仓完全相同。

## 回测边界

回测使用当日确认后的技术信号决定下一净值日是否持有，并默认每次进出扣除 `0.15%` 成本。它尚未回测客户止盈目标和五档动作，也没有模拟每只基金不同的申购费、赎回费、持有期费率、确认日、暂停申购、限购及大额赎回影响，不能替代针对具体基金的实盘成本测算。

## 数据与隐私

- 历史净值和基金搜索来自东方财富公开基金页面。
- 服务端会在本机 `.cache` 目录缓存数据 6 小时；上游暂时失败时可回退到旧缓存。
- 自选基金、客户分组、持仓金额、成本、止盈目标和风险风格仅保存在浏览器 `localStorage`，服务端没有用户数据库。
- 组合查询改用 HTTPS POST 请求体，基金代码不会出现在普通组合查询 URL 中。服务端仍会临时处理查询所需的基金代码。
- “本地隐私与备份”可以导出 AES-256-GCM 加密保险箱；密码不保存、不上传，忘记后无法找回。
- 在共享电脑上可以使用“清除当前浏览器数据”，经二次点击确认后删除本机保存的基金和策略。
- 新访客默认空组合。不同浏览器互相隔离，共用同一个操作系统浏览器配置的人仍可能看到该配置保存的数据。
- 公开网站接口可能发生变化，项目已经将数据源封装在 `src/data-source.mjs`，便于后续增加 AKShare 或其他备用源。

完整隐私边界见 `PRIVACY.md`。

## “实时”口径

场外基金没有像 ETF 那样连续撮合成交的盘中价格。主动管理基金的盘中估值还会受到持仓披露滞后、调仓未知和港股汇率等因素影响，因此本项目不会把估算净值冒充真实净值。

这里的实时跟踪指：

- 定时检查官方数据是否更新；
- 新净值出现后自动重算全部指标；
- 五档仓位动作发生变化时触发提醒；
- 页面明确展示净值日期、数据一致性和延迟情况。

## 重要说明

本项目是研究与信息整理工具，不构成个性化投资建议、收益承诺或自动交易指令。技术指标基于历史净值，存在滞后、假突破和参数失效风险。实际决策还应结合基金类型、跟踪指数、基金经理变化、估值、资产配置、资金期限、申赎费用与个人风险承受能力。
