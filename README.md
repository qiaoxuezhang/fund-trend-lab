# 净值罗盘

一个面向中国场外公募基金的本地优先趋势研究工具。输入基金代码或名称后，可查看历史净值、NAV-KDJ、MA、MACD、RSI、回撤、波动率、结构校准分、历史相似状态以及简化信号回测。

图表支持近 `3个月`、`6个月`、`1年`、`3年` 和全部历史区间。KDJ、MACD、RSI 均提供独立图例；短区间净值样本不足时，回测会明确显示“样本不足”，不会回退并冒充为该区间结果。

公开版本不内置任何个人基金、金额或收益率。每个新浏览器默认空组合，用户自行添加基金；组合监控、分组、成本、止盈目标和风险设置保存在该浏览器中。

## 启动

Windows 下双击 `start.cmd`，或在 PowerShell 中运行：

```powershell
.\start.ps1
```

本机浏览器打开：

```text
http://127.0.0.1:4173
```

同一 Wi-Fi 下的手机或电脑可以打开当前局域网地址：

```text
http://192.168.31.151:4173
```

局域网 IP 可能在路由器重连后变化；长期推广应使用云平台固定 HTTPS 地址，而不是开放家庭路由器端口。

如果电脑已安装 Node.js 20 或更高版本，也可以运行：

```powershell
npm start
```

项目没有第三方运行时依赖，不需要执行 `npm install`。

## 组合监控与提醒

- 使用场外基金低频检查策略：交易时段每 60 分钟、正式净值更新窗口每 30 分钟、普通非交易时段每 2 小时、休市日每 6 小时检查一次。
- 只有发现净值日期或数值变化时，才重新下载完整历史并计算指标。
- 通过历史净值页面和基金快照接口交叉核对日期、单位净值。
- 日期延迟、数值不一致或历史样本不足时，统一显示“等待确认”，不产生新增仓位动作。
- 点击“策略与止盈目标”可以设置默认止盈目标、每只基金的单独目标和持仓成本净值。
- 点击页面的“开启风险提醒”后，网页或 PWA 保持打开时，仓位动作变化、板块代表更换、退出前三或风险恶化会发送浏览器通知。纯本地免费模式无法在网页完全关闭后继续计算和推送。

旧版本从截图金额反推的参考份额只存在原使用者浏览器中，不再写入公共前端源码。公开部署后的其他用户不会看到这些信息。客户可在策略设置中填写持仓成本净值，以校准持有收益和止盈目标。

## 公网部署

项目包含 `Dockerfile`、`compose.yaml` 和 `render.yaml`。任何支持 Docker 和 HTTPS 的平台都可以运行：

```powershell
docker compose up -d --build
```

免费邀请测试将 `HOST` 设为 `0.0.0.0`，将 `ALLOW_INDEXING` 设为 `false`。页面已经包含 Web App Manifest、Service Worker、分享入口和安装入口，可在支持 PWA 的手机或电脑上安装为独立应用。

Render Free 不需要用户数据库：自选、分组、成本、交易和目标仍只保存在当前浏览器。免费实例休眠或重新部署时只会丢失可重新生成的服务端缓存，不会删除客户本机数据。需要换设备时使用 AES-256-GCM 加密保险箱手动迁移。

完整部署与域名配置见 `DEPLOYMENT.md`，当前访问状态见 `PUBLIC_ACCESS.md`。

项目审查结论与后续路线见 `AUDIT.md`，安全问题提交方式见 `SECURITY.md`。

容器监听 `0.0.0.0:4173`，健康检查地址为 `/api/health`。生产环境必须使用 HTTPS；不能直接把开发电脑的 `4173` 端口暴露到公网。

部署到 Render 时，可以将仓库连接为 Blueprint，平台会读取 `render.yaml` 构建 Docker 服务。其他云平台使用相同 `Dockerfile` 即可。

## 指标口径

场外基金通常每天只有一个单位净值，不具备股票日线的开盘、最高、最低和收盘四价。本项目优先使用累计净值计算趋势，降低现金分红造成的机械跳空影响；页面顶部仍展示最新单位净值。`NAV-KDJ` 将最近 9 个净值日的最高累计净值与最低累计净值作为随机指标区间：

```text
RSV = (当日净值 - N日最低净值) / (N日最高净值 - N日最低净值) * 100
K = 2/3 * 前一日K + 1/3 * RSV
D = 2/3 * 前一日D + 1/3 * K
J = 3K - 2D
```

因此它适合判断净值在近期波动区间的位置和动能变化，但不等同于证券标准 KDJ。

综合趋势分还会考虑：

- 净值相对 MA20、MA60 的位置
- MA20 近 5 个净值日的方向
- NAV-KDJ 金叉、死叉与相对位置
- MACD 柱体方向及零轴穿越
- RSI 强弱及追涨风险
- 20 日和 60 日净值动量
- 当前回撤和 20 日年化波动率

系统另外把当前结构分为 `上行结构`、`短期回调`、`低位修复`、`震荡混合` 和 `趋势破坏`。低位修复会单独计算 0 至 100 的“修复动力证据分”，检查净值重回 MA20、MA5/MA10、MACD 转正及改善、RSI、近期收益和 MA60/MA120 骨架，同时扣除 KDJ 过热、急涨和高波动。该分数是证据完成度，不是上涨概率。趋势破坏必须由长期骨架和中期趋势同时恶化触发，历史回撤不能单独触发退出结论。

## 自选与持仓动作解释

- 仅自选基金：`自选等待确认`、`小额试仓候选`、`分批建仓候选`、`暂不介入`。
- 已有持仓：`持有观察`、`持有并按计划加仓`、`持有，暂停加仓`、`分批止盈`、`降低仓位`、`紧急避险`。
- `分批建仓候选` 必须同时通过趋势结构、动能触发和最近披露持仓基本面三层确认；单一金叉不生成完整建仓提示。
- `小额试仓候选` 仅表示趋势与动能通过、但持仓财务覆盖不足，不能冒充完整三层确认。
- `分批止盈` 使用客户默认或单基金目标，范围为 `5%` 至 `200%`，参考分 2 至 3 次执行。
- `降低仓位` 要求中长期风险同步恶化；历史深回撤只作风险背景，不能单独触发退出。
- `紧急避险` 由异常单日跌幅、短期快速深跌或深跌伴随波动急升等独立风险门控触发，优先于止盈和任何正向信号。执行前仍需核对分红、巨额赎回、净值异常、持有期和赎回费。

动作判定顺序为：紧急风险、数据与样本校验、中长期高风险、客户止盈目标、三层建仓确认、持仓观察或自选等待。风险门控拥有独立否决权，不依靠总分累加凑票。

稳健、均衡、积极三种模式只调整触发阈值，不会改变底层历史数据。

页面展示 `-10.0` 到 `+10.0` 的多周期校准分。模型不把十多个相关指标直接累加，而是先形成四个独立层次：`长期状态 35%`、`中期趋势与修复 30%`、`短期择时 25%`、`风险约束 10%`。每层内部使用连续有界变换统一量纲，再按权重合并；风险层只扣分，不制造买入信号。

结构状态是综合分的上层约束：趋势破坏固定限制在 `-4.0` 以下；短期回调限制在 `-2.0` 至 `+3.0`，低位修复限制在 `-1.0` 至 `+3.5`，震荡混合限制在 `-2.5` 至 `+2.5`。这些客观结构区间不随客户风险风格变化；稳健、均衡、积极只影响动作阈值。若不同周期冲突，页面会增加“结构一致性约束”项目，公开显示原始分被修正的原因。

“独立证据组一致性”按长期状态、中期趋势与修复、短期择时三个方向层的权重计算。低于 `55%` 表示分歧较大；`55%-69%` 仅观察；`70%-79%` 可进入候选验证；`80%` 以上表示方向证据高度一致。它不是上涨概率，也不是经过样本外验证的收益概率。

## 多周期趋势模型

当前多周期校准模型主要考虑：

- 长期状态层：MA60/MA120、MA60 近 10 个净值日方向和 120 日风险调整动量。
- 中期趋势与修复层：累计净值/MA20、MA20/MA60、MA20 近 5 个净值日方向及 20/60 日风险调整动量。
- 短期择时层：MA5/MA10、5 日动量、MACD 及其改善速度、RSI、低权重 NAV-KDJ 和最近 20 个净值日上涨日占比。
- 风险约束层：近 250 个净值日回撤、年化波动率、RSI/KDJ 过热和短期急涨，只产生非正贡献。

单日涨跌不直接进入趋势分。NAV-KDJ 只作为短周期辅助，不会单独触发分批建仓或风险退出动作。

详情页新增“多周期决策台”，分别展示短期 `5-20` 个净值日、中期 `20-60` 个净值日和中长期 `60-120` 个净值日的独立方向，并公开 MA5/MA10、MA20/MA60、MACD 和 KDJ 最近一次金叉或死叉的新鲜度。所谓“三倍选股法”没有统一权威定义；本项目不迁移依赖个股成交量的“三倍量”口诀，而采用可解释的三层确认：

1. 趋势结构：净值和 MA20/MA60/MA120 的位置与方向。
2. 动能触发：MA5/MA10、MACD、KDJ 和短期动量，相关指标在层内合并，避免重复计票。
3. 底层验证：最近披露持仓的财务覆盖和基本面分；新闻与政策只作背景核验。

主动管理场外基金没有可靠、连续披露的每日成交量或申赎量，因此项目不会制造“成交量指标”。详情页的“交易量”仅指客户自己记录的实际买卖金额和确认份额。对于明确跟踪指数的基金，后续可以单独映射对应指数或 ETF 的成交量和市场宽度，但必须与基金净值信号分开展示。

## 自选趋势前三与交易复盘

- 首页“趋势强度前三”只比较当前浏览器自选基金，优先展示正式净值已校验的基金，并按结构校准分排序；同一基金的 A/C 等份额先合并为一类，不冒充全市场排名。
- 首页“全市场板块代表”同时抽取近1月和近3个月公开排行候选，合并同一基金的 A/C 等份额，按最近披露持仓识别主导板块，同一板块只保留综合验证后最优的一只。
- 全市场候选还要通过正式净值一致性、中长期结构、证据组一致性、回撤、波动、RSI 和前五大可研究持仓财务覆盖检查。结果分为“可研究建仓”“等待回撤”“继续跟踪”“仅作强势对比”等，不把涨幅榜直接当成买入榜。
- 浏览器会在本地记录每轮板块代表，并在低频净值检查时比较新旧结果；代表更换、退出前三、建议降级、结构恶化、结构校准分明显下降、一致性下降或回撤扩大时生成失效预警。预警只保存在当前设备。
- 详情页可以记录历史买入、卖出、确认净值、金额、份额和备注；记录仅保存在当前浏览器，并自动进入加密保险箱。
- 历史交易会以买卖标记显示在累计净值图上，方便结合当时趋势结构复盘执行纪律。

## 显示颜色与客户分组

- 上涨、正收益、偏强加分使用红色。
- 下跌、负收益、偏弱扣分使用绿色。
- 数据校验成功仍使用状态绿色，不与涨跌含义混淆。
- 默认只有“我的持仓”和“未分组”。客户可以新建、删除自己的分组，并在组合表格中移动基金。
- 客户分组保存在浏览器 `localStorage`。删除自定义分组时，其中基金自动移到“未分组”。
- 系统行业标签与客户分组彼此独立：标签根据最近一期前十大持仓及权重生成，用于把持仓板块相近的基金放在相邻位置。

## 持仓公司与基本面研究

- 基金持仓来自最近一期公开季度或半年度报告，页面始终展示报告期和前十大集中度，不把披露持仓冒充当前实际仓位。
- 对前十大持仓公司读取最新标准化财报、公告、公司相关新闻以及行业政策信息，并展示各自披露日期或发布时间。
- 公司研究分主要依据营收增速、归母净利润增速、净利润正负、ROE、毛利率和经营现金流；公告关键词只占较低权重。
- 基金基本面分按持仓权重聚合。财报覆盖足够时，组合页综合分使用 `75%` 趋势分和 `25%` 基本面分。
- 基本面偏弱可以把技术面的新增仓位候选降级为等待确认；基本面不能脱离趋势单独生成分批建仓提示。
- 新闻和政策搜索必须命中公司名，或同时命中行业词与政策词。它们仅用于背景核验，不直接计入买卖分，避免短期消息噪声主导判断。
- 系统按前十大持仓的加权重合度计算相似基金。该相似度反映已披露组合，不代表当前实时持仓完全相同。

## 回测边界

回测使用当日确认后的技术信号决定下一净值日是否持有，并默认每次进出扣除 `0.15%` 成本。页面横向比较“三层技术确认”“单一 MA5/MA10 金叉”“旧综合分规则”和“同期持有”，同时展示收益、最大回撤、切换次数和有完整交易时的胜率。自动化测试会验证追加未来数据不会改变历史决策，避免前视偏差。

这些结果仍属于单基金历史样本内纪律检查，不能证明未来有效。系统尚未模拟每只基金不同的申购费、赎回费、持有期费率、确认日、暂停申购、限购及大额赎回影响，也不能替代滚动样本外和多基金横截面验证。

## 数据与隐私

- 历史净值和基金搜索来自东方财富公开基金页面。
- 服务端会在本机 `.cache` 目录缓存数据 6 小时；上游暂时失败时可回退到旧缓存。
- 自选基金、客户分组、持仓金额、成本、止盈目标和风险风格仅保存在浏览器 `localStorage`，服务端没有用户数据库。
- 组合查询改用 HTTPS POST 请求体，基金代码不会出现在普通组合查询 URL 中。服务端仍会临时处理查询所需的基金代码。
- “本地隐私与备份”可以导出 AES-256-GCM 加密保险箱；密码不保存、不上传，忘记后无法找回。
- 在共享电脑上可以使用“清除当前浏览器数据”，经二次点击确认后删除本机保存的基金和策略。
- 新访客默认空组合。不同浏览器互相隔离，共用同一个操作系统浏览器配置的人仍可能看到该配置保存的数据。
- 公开网站接口可能发生变化，项目已经将数据源封装在 `src/data-source.mjs`，便于后续增加 AKShare 或其他备用源。

完整隐私边界见 `PRIVACY.md`。

## 访问控制与开发者权益

- 将 `APP_ACCESS_PASSWORD` 设置为非空环境变量后，主页和全部基金 API 都需要先通过服务端密码验证；密码不会进入前端资源、Git 提交或浏览器本地存储。
- `APP_SESSION_SECRET` 用于签发 `HttpOnly`、`SameSite=Strict` 的短期访问 Cookie，生产环境通过 HTTPS 设置 `Secure` 属性。
- 访问密码只能控制未授权访问，不能阻止已获授权者截图、记录结果或分析浏览器已经接收的前端代码。
- 项目采用保留全部权利的专有 `LICENSE`。准备长期运营时，建议同时将 GitHub 仓库改为私有、保留 Git 提交证据，并办理计算机软件著作权登记。

## “实时”口径

场外基金没有像 ETF 那样连续撮合成交的盘中价格。主动管理基金的盘中估值还会受到持仓披露滞后、调仓未知和港股汇率等因素影响，因此本项目不会把估算净值冒充真实净值。

这里的实时跟踪指：

- 定时检查官方数据是否更新；
- 新净值出现后自动重算全部指标；
- 五档仓位动作发生变化时触发提醒；
- 页面明确展示净值日期、数据一致性和延迟情况。

## 重要说明

本项目是研究与信息整理工具，不构成个性化投资建议、收益承诺或自动交易指令。技术指标基于历史净值，存在滞后、假突破和参数失效风险。实际决策还应结合基金类型、跟踪指数、基金经理变化、估值、资产配置、资金期限、申赎费用与个人风险承受能力。
